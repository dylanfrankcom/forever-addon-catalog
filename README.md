# Forever Add-on Catalog

The list of add-ons [Forever Add-on Manager](https://github.com/dylanfrankcom/forever-addon-manager) can find and install for WoW Forever.

> **Status:** public and still being built. [Forever Add-on Manager](https://github.com/dylanfrankcom/forever-addon-manager) already reads this catalog at start and before each update check, and more add-ons, entry fields and the release checker are on the way.
>
> Not affiliated with or endorsed by Blizzard Entertainment. Every add-on belongs to its author; entries only say where the author publishes it.

## What's here
| Path | What |
|---|---|
| `catalog.json` | One entry per add-on: its sources (GitHub, CurseForge, Wago), folders, editions, required and optional add-ons, conflicts, notes and withdrawn releases. One record per author: their name, homepage, profiles and support pages. Generated by `scripts/generate.cs`, never edited by hand. |
| `overrides/` | Hand corrections, one file per entry (`<id>.json`), and `_authors.json`, the author records written by hand. |
| `optout.json` | The never-add list: repos and accounts that are never listed, each with why (see [Your choice](#your-choice-listed-link-only-or-not-at-all)). |
| `addons/` | A detail file per add-on released on GitHub (`<id>.json`): its README, recent release notes, screenshots, stats, languages and technical details, which the app fetches only when the add-on is opened. Written by `scripts/details.cs`, never by hand; the format is `schema/details.schema.json`. |
| `icons/` | Add-on icons, converted to PNG from each add-on's own `.toc` IconTexture. |
| `schema/catalog.schema.json` | The format. |
| `.github/workflows/validate.yml` | On every PR: runs each script's self-test and validates `catalog.json`; changed entries must come with a version bump. |
| `scripts/` | Discovery, the release check, the generator and validation: .NET file-based programs (see `scripts/README.md`). |
| `status.json` | Written by the checker job, never by hand: which releases list the Forever Interface (coming with the catalog checker, app 0.6.0). |
| `versions.json` | Generated with `catalog.json`, never by hand: the latest checked release of each add-on for each edition, with its size and hash, so the app finds updates without asking GitHub. Its format is `schema/versions.schema.json`. |

The full format, with a description of every field, is in [`schema/catalog.schema.json`](schema/catalog.schema.json).

## Rules
- **The catalog is data, not instructions.** It says where to look. The app still checks every download (hashes, the Forever `.toc`, no executables) and asks before installing.
- **IDs are stable:** they never change and are never reused.

## Where entry fields come from
The catalog is generated (`scripts/generate.cs`): every add-on whose latest GitHub release passed the release check is listed, with values from what the author published (the release's `.toc`, the repository's description and topics). Nothing is guessed: when the author doesn't list something, the field is left out. Hand corrections live in `overrides/`, and each entry's `from` says where its values came from. The details are in `schema/README.md`.

- **`author`** (required): who made the add-on, as its pages credit them. Each author has one record in `authors`, shared by all their add-ons, with these fields:
  - **`name`**: how the author is shown.
  - **`homepage`** (optional): the author's own site, when they have one. Not an add-on's page.
  - **`profiles`** (optional): the author's own pages on GitHub, Wago and CurseForge, one per site, linked from their pages there.
  - **`sponsor`** (optional): see below.
- **`added`** (required on new entries): the day the entry joined the catalog. Entries from before the field existed have the date of the commit that first added them.
- **`links.repository`** (optional): the public GitHub or GitLab repository that holds the add-on's source code, even when the catalog downloads it from CurseForge or Wago. The app marks add-ons whose code is public. Only a repository with the code counts: one that only hosts issues, or a link to a repository that isn't public, is left out. The catalog doesn't record licences: each add-on's repository states its own.
- **`links.issues`** (optional): where players report problems to the author. This is the repository's issues page when it has issues turned on. Otherwise it's the tracker the author links from their CurseForge or Wago page, if that link works. The app's Report a problem link uses it.
- **`sponsor`** (optional, in the author's record): a list of the `https` pages where people can support the author (Patreon, Ko-fi, Buy Me a Coffee, PayPal, GitHub Sponsors …). The app shows each as its own link, grouped by author. Only pages the author lists themselves are included, never guessed, and a page that's listed under two addresses is included once. A wrong link would send a player's money to the wrong person, so they're checked:
  - **From the author's own repos only:** each listed repo's `FUNDING.yml` (or the owner's `.github` repo's), as GitHub reads it. Never from a fork or another account's repo.
  - **GitHub Sponsors:** only an account that has a Sponsors listing and is the repo's owner, or a public member of the organisation that owns it. It comes first.
  - **Everything else:** in the file's order, `https` only (an `http://` link, or one written without a scheme like `paypal.me/name`, is read as the same page over `https`), and a shortened link (bit.ly and the like) is listed as the page it leads to, found from the shortener's redirect, never as the short link.
  - **Reported:** every refused link, and every link that appears, changes or goes away, is listed in the generator's report for the maintainer to look at.
  - Authors written by hand (`overrides/_authors.json`) keep their own list, which can also include the Donate button on their CurseForge or Wago page.
- **`downloads`** (optional): how often the add-on is downloaded, for sorting and its page: every release's files (`total`), the latest release's (`latest`) and the day they were read. These are only GitHub's own public download counts for release files, read once a week. The app tracks nothing: its installs download from GitHub, so they're already part of these counts. Add-ons that aren't released on GitHub have none.
- **`trust`** (optional): what players can go on to trust the add-on, from public data only: whether a workflow in its own repo built the release file (GitHub's build record), when the repo and its owner's account were made, its releases and stars, the author's `X-Forever-Catalog` marker, the badges the app shows ("Built by its own repo", "New") and warning signs. A warning sign never keeps an add-on out: the app is more careful with it instead (a longer wait for new releases, and left out of Update all). The rules are in [schema/README.md](schema/README.md#trust-signals).
- **`icon`** (optional): a small square PNG for the add-on, shown on its cards in the app. It's the icon the author ships in the add-on itself (the `.toc`'s IconTexture, when it's one of the add-on's own files), converted to PNG and kept in this repo. Never game art and never drawn here; without one, the app shows the add-on's tag icon.

## For add-on authors
Thanks for making add-ons for Forever.

### How listing works
The catalog lists every add-on whose latest GitHub release lists the Forever Interface and passes the release check (it's downloaded and inspected like the app does before installing). It's found by searching public repositories for `.toc` files; nobody has to submit it. Its name, summary and links come from what you published. The app installs and updates it from your GitHub release, so every install counts in your release's download numbers.

### Your choice: listed, link only, or not at all
- **Opt out:** open a [Remove my add-on, or make it link only](https://github.com/dylanfrankcom/forever-addon-catalog/issues/new?template=author-choice.yml) issue from the GitHub account that owns the repository, or add `## X-Forever-Catalog: no` to your `.toc` (the catalog reads it on its next run and stops listing the add-on). Removed add-ons go on the never-add list (`optout.json`, with the reason and the day), so discovery never lists them again.
- **Link only:** the same form. Your add-on stays listed, but the app never downloads it: players get a link to the page you choose and download it there.
- **Opt in:** nothing is needed, but `## X-Forever-Catalog: yes` in your `.toc`, or the `wow-forever` topic on your repository, says you're happy to be listed, and the app may show it.

### Tips
A few things that make life easier for players who use the app:

- **GitHub releases install in one click.** The app installs and updates add-ons straight from a GitHub release. When an add-on is only on CurseForge or Wago, the player downloads the zip from that site themselves and hands it to the app, every update. If you publish there, attaching the same zip to a GitHub release gives players the one-click path. The [BigWigs packager](https://github.com/BigWigsMods/packager) can do it in the same run as your CurseForge and Wago uploads: give it a GitHub token and it creates the release too.
- **List the Forever Interface in your `.toc`.** Only add-ons whose current release lists it are in the catalog. Separate files per game version are fine: a name that says which one is Forever's (ending in `-forever`, say) helps players pick the right file.
- **Suggesting your own add-on** works like any other request: the [Add an add-on](https://github.com/dylanfrankcom/forever-addon-catalog/issues/new?template=addon.yml) form.
- **Your support page comes first.** Entries link to the support pages and issue tracker you list yourself (see `sponsor` and `issues` above). The catalog and the app take no donations, so any support goes to you.
- **Your links live in one place.** Your homepage, your GitHub, Wago and CurseForge profiles and your support pages are kept once, in your author record, for all your add-ons. The app shows them on your author page. To add or change them, open an issue with the **Task** form.
- **Something wrong in your entry** (a moved repo, a new folder): open an issue with the **Task** form.
## Contributing
Know an add-on that works on Forever? Ask for it with the [Add an add-on](https://github.com/dylanfrankcom/forever-addon-catalog/issues/new?template=addon.yml) form. Add-ons released on GitHub are found and checked automatically (the release, its files and its `.toc`); the form is for add-ons that are missed, and for those only on CurseForge or Wago. Questions are welcome as issues, with the Question form.

Some add-ons work on Forever but can't be listed, for example when their only source has turned off downloads by other apps. They're recorded as issues labelled [`unavailable`](https://github.com/dylanfrankcom/forever-addon-catalog/issues?q=label%3Aunavailable) (there's an [Add-on that can't be listed](https://github.com/dylanfrankcom/forever-addon-catalog/issues/new?template=unavailable.yml) form), each saying what would make it possible. Comments there are welcome when an author changes something. Pull requests from outside the project aren't accepted: see [CONTRIBUTING.md](CONTRIBUTING.md).

The catalog and the app are free and open source, take no donations, and are developed by AI agents (Claude Code) under the maintainer's direction.
